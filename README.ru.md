# QuickTask

Виджет-панель для заметок и задач, который живёт незаметным ярлычком у края экрана и разворачивается по клику или хоткею.

![QuickTask](screenshots/quick-task.gif)

## Ключевые функции

- Ярлычок 36×36 px у края экрана, разворачивается в сайдбар (380 px) по наведению курсора, клику или хоткею `Ctrl+Alt+T`; сворачивается сам при потере фокуса.
- Задачи хранятся как обычные `.md`-файлы с YAML-фронтматтером (`done`, `archived`, даты) — открываются в Obsidian, VS Code, любом текстовом редакторе.
- Отслеживание внешних изменений файлов (Watchdog) — правки вне приложения подхватываются на лету.
- Модальный редактор описания задачи с поддержкой Markdown (CodeMirror) и автосохранением.
- Тёмная и светлая темы, переключение одной кнопкой.
- Не занимает место в таскбаре и `Alt+Tab` (окно в стиле ToolWindow).
- Выбор папки хранения задач, настройка высоты сайдбара, перетаскивание и закрепление (**Pin**) ярлычка.

## Системные требования

Windows 10 или 11 (64-bit). Используется системный компонент WebView2 — дополнительно ничего ставить не нужно.

## Установка

Скачайте `QuickTaskPortable.zip` со страницы [Releases](https://github.com/xelay/QuickTask/releases) и запустите. Python и другие зависимости не требуются.

Хотите запустить из исходников или собрать `.exe` сами? Инструкция — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Управление

- `Ctrl+Alt+T` — развернуть ярлычок в сайдбар и сразу создать новую задачу. Комбинацию можно сменить или отключить в настройках.
- Наведите курсор на верхнюю часть ярлычка (иконка-закладка) или кликните по ней — сайдбар развернётся; уберите курсор — свернётся обратно, если не закреплён кнопкой **Pin**.
- Зажмите левую кнопку мыши на нижней части ярлычка (иконка-«гамбургер») и потяните вверх или вниз — ярлычок переместится по краю экрана.

## Где хранятся данные

- Задачи — `~/Documents/QuickTasks/` по умолчанию (папку можно сменить в настройках на любую другую).
- Настройки приложения — `~/.quicktask/config.json`.
- Служебный кэш метаданных — `~/.quicktask/cache/<хэш пути к папке>.sqlite3` (см. «Кэш метаданных» ниже).

### Что сканируется в папке задач

QuickTask смотрит только на файлы `*.md`, лежащие прямо в корне выбранной папки — без вложенных подпапок. Всё остальное приложение не трогает и никак не замечает:

- вложенные подпапки — можно спокойно держать рядом вложения, картинки, архив по годам, папку `.obsidian` и т.п.;
- файлы с любым другим расширением;
- скрытые и системные файлы.

### Формат файла задачи

Каждая задача — обычный `.md`-файл с YAML-фронтматтером:

```markdown
---
done: false
archived: false
urgent: false
created_at: 2026-09-10T12:00:00
updated_at: 2026-09-10T12:05:00
order_key: a0
---
# Заголовок задачи

Текст описания в Markdown.
```

- `done`, `archived`, `urgent` — флаги состояния.
- `created_at` / `updated_at` — таймстемпы.
- `order_key` — короткий строковый ключ ручной сортировки (см. ниже); появляется только у задач, которые хоть раз переставляли вручную.
- Заголовок задачи — первая строка `# ...` в теле файла; если её нет, используется имя файла.
- Любые другие поля фронтматтера, добавленные вами вручную (теги, ссылки и т.п.), QuickTask не трогает и сохраняет как есть.

### Работа через Obsidian или любой другой редактор

Так как задачи — это обычные `.md`-файлы, папку можно открыть как хранилище (vault) в Obsidian или в любом редакторе с поддержкой Markdown:

- правки, сделанные снаружи (в Obsidian, VS Code, блокноте), подхватываются на лету — приложение следит за папкой (Watchdog) и перечитывает только изменившиеся файлы;
- поля `done` / `archived` / `urgent` / `created_at` / `updated_at` / `order_key` будут видны в Obsidian как обычные Properties; `done`/`archived`/`urgent` безопасно переключать и снаружи, а `order_key` и таймстемпы лучше не трогать руками;
- переименование файла снаружи задачу не ломает — вся информация, включая порядок, хранится в самом файле;
- собственные дополнительные поля фронтматтера и теги Obsidian QuickTask не трогает и сохраняет как есть.

### Хранение в git-репозитории

Папку с задачами можно смело сделать git-репозиторием — `git init` в ней ничего не сломает:

- обычные действия (создание задачи, отметка выполненной, редактирование, перетаскивание в списке) меняют ровно один `.md`-файл за раз — общего файла-индекса, который переписывался бы целиком, больше нет;
- добавлять что-либо в `.gitignore` не обязательно: кэш (`~/.quicktask/cache/`) и настройки (`~/.quicktask/config.json`) физически лежат вне папки с задачами и никогда туда не попадут. 

### Кэш метаданных (SQLite)

Для ускорения работы со списком задач QuickTask держит служебный кэш — по одному файлу `~/.quicktask/cache/<хэш пути к папке>.sqlite3` на каждую настроенную папку задач. Это **не источник данных, а одноразовый, безопасно удаляемый кэш для скорости**:

- в нём дублируются уже распарсенные из `.md`-файлов данные, чтобы не перечитывать всю папку при каждом действии;
- источником истины всегда остаются сами `.md`-файлы — кэш можно удалить в любой момент, приложение просто пересоберёт его заново при следующем запуске;
- читать или редактировать этот файл напрямую через SQL не нужно: изменения, внесённые так, не попадут обратно в `.md`-файлы и будут перезаписаны при следующем изменении соответствующей задачи.
